# VerifForge Next upgrade roadmap

VerifForge Next develops the local engineering investigation workbench from the [submitted VerifForge source](https://github.com/desanv01/VerifForge/tree/5453a5759af8d3529f2226ca9880f46eac618c18). The original repository contains the hackathon evidence and contribution record.

The first integration target is one supported current path from an exact design and requirement through a real experiment, independent verdict, replay, checked candidate, and workbench readback. Implementation, import, execution and repair each have distinct evidence. Historical demonstrations retain their original scope.

## Delivery order

1. Qualify trusted role startup and current schema on an isolated empty target. Preserve and restore original data through a separate cold boundary before populated adoption.
2. Land independent fixes in parallel. Reconcile recorded evidence associations, qualify one durable RTL witness and candidate flow, advance bounded native Vivado and KiCad checks, and prepare independent cross-domain facts.
3. Verify the current workbench through real API and browser readback, exact imports, replay, exports and candidate reports. Settle owned resources.
4. Establish actual recovery behavior, comparable evaluation, release reproduction and supported claims. Analog and ASIC investigations remain stretch scope. Broader software and desktop adapters follow the primary engineering gates.

The [demonstration and evidence guide](https://github.com/desanv01/VerifForge/blob/5453a5759af8d3529f2226ca9880f46eac618c18/docs/project/DEMO.md) describes what was shown in the original submission. Follow the open issues for successor qualification.

## Contributions

Keep finite changes in scoped pull requests and cite the relevant acceptance issue. Record the source revision, actual checks, evidence scope and remaining requirement. Reuse applicable prior results. Keep private configuration, credentials, databases and evidence outside public changes.
